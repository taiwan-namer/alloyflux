# 構想階段：供給者節點、無痕與請求來源設計

整理日期：2026-11-10（節點 MVP 落地後更新）  
狀態：**買家任務＝Node Agent；OAuth 訂閱研究與正式任務隔離**  
詳見 [`04_Node_Agent_MVP.md`](./04_Node_Agent_MVP.md)。

---

## 0. 先看結論（對照表）

| 項目 | 構想階段 | 目前程式碼 |
|---|---|---|
| OAuth 訂閱池 | 有 | **主線**：Gemini／ChatGPT／Grok |
| Token 存在哪 | 理想上供給者裝置 | **節點 claim 後**：`data/node-creds/`；平台只留 stub（`delegatedToNode`） |
| 請求從哪裡發出 | 供給者裝置 | **節點在線／已委託**：平台只派 model＋messages；節點本機持 Token 打上游 |
| 出口 IP 驗證 | — | `/api/nodes/egress`：平台 vs 節點公網 IP；同機／同寬頻會相同 |
| 住宅 IP／指紋偽裝 | 構想有討論 | **刻意不做**（非產品範圍） |
| 無痕 | 臨時對話＋刪除 | ChatGPT／Grok `store: false`；無自動 DELETE 官方對話 |
| 官方 API 保底 | 有 | env Key／OpenRouter |
| 強制節點 | — | `REQUIRE_SUPPLIER_NODE=1` 時禁止平台代發 OAuth |

一句話：

> Token 在節點本機；平台只負責調度與代發「任務」（不是代發帶 Token 的上游 HTTP）。  
> 要驗證出口差異，請把節點開在另一台網路。不做住宅 IP／指紋偽裝。

---

## 1. 現行資料流

```text
買家網頁 Prompt
  → 平台 Orchestrator 選 OAuth 貨源
  → 若 delegated 或節點在線：enqueue 聊天任務（無 Token）
  → 供給者 npm run supplier-node 長輪詢 /api/nodes/poll
  → 節點用本機 creds 打 Google／OpenAI／xAI
  → 串流 event 回平台 → 買家
```

節點首次上線：`claim_creds` → 平台清空 Token → 本機寫入 `data/node-creds/{sourceId}.json`。

---

## 2. 構想中曾討論、目前不做的部分

- Sticky Residential Proxy／住宅 IP 池  
- TLS／JA3／瀏覽器指紋偽裝  
- 形態 B「雲端代管＋假家用出口」  

這些屬於規避偵測，**不在實作範圍**。產品只做到：真實供給者裝置網路出口＋憑證本地化。

---

## 3. 無痕（構想 vs 現況）

| 機制 | 構想 | 現況 |
|---|---|---|
| `store: false` | 有 | ChatGPT／Grok 有；Gemini 無對應旗標 |
| 回覆後 DELETE conversation | 有 | **無** |
| 平台自存對話 | 有 | **有**（SQLite） |

「供給者畫面看不到」≠「供應商伺服器沒有紀錄」。

---

## 4. 程式位置

| 能力 | 位置 |
|---|---|
| 調度 | `lib/gateway.ts` |
| 節點派工／egress | `lib/nodes.ts`、`app/api/nodes/*` |
| claim／stub | `lib/sources.ts` `claimOAuthCredsForNode` |
| 上游串流 | `lib/providers.ts`（平台走 `streamChatViaSupplierNode`；節點走 `streamOAuthLocally`） |
| 節點程式 | `scripts/supplier-node.ts`（`npm run supplier-node`） |
| UI | `/sources` 節點卡＋出口 IP 對照 |

---

## 5. 給工程師的一句話

> OAuth 訂閱池仍是主線。節點 MVP 已把 Token 與上游 HTTP 移到供給者裝置；平台只派工。住宅 IP／指紋不在範圍內。
